## Реализация

Приложение предоставляет REST API для управления данными фитнес-клуба. Реализованы CRUD-операции с клиентами, тренерами, специализациями, залами и персональными тренировками, а также аналитические запросы.

В отличие от предыдущей лабораторной работы, данные хранятся в реляционной базе данных PostgreSQL. Для взаимодействия с базой используется Entity Framework Core и отдельный инфраструктурный проект `FitnessClub.Infrastructure.EfCore`.

Приложение построено с использованием слоистой архитектуры. Предметная область, контракты и бизнес-логика отделены от конкретной реализации хранения данных. Репозитории выполняют асинхронные операции с помощью EF Core.

Для настройки модели базы данных используются конфигурации сущностей и миграции. При запуске API миграции применяются автоматически. Начальные данные добавляются через конфигурацию модели EF Core.

Для проверки входных данных используются Data Annotations. Конфликты ограничений базы данных и конкурентного изменения обрабатываются отдельно и возвращаются в виде HTTP 409. Для просмотра и тестирования HTTP-методов используется Scalar на основе OpenAPI.

Запуск и оркестрация приложения выполняются с помощью .NET Aspire. Aspire запускает PostgreSQL в Docker-контейнере, передаёт строку подключения API и ожидает готовности базы данных.

## Работа с базой данных

Для хранения данных используется PostgreSQL. Контекст `FitnessClubDbContext` находится в проекте `FitnessClub.Infrastructure.EfCore` и содержит наборы данных для основных сущностей:

- Клиенты (`Clients`).
- Тренеры (`Trainers`).
- Специализации (`Specializations`).
- Залы (`Halls`).
- Тренировки (`Trainings`).

Настройка таблиц и связей вынесена в отдельные классы конфигурации в каталоге `Configurations`. Для клиентов и тренеров используются отдельные таблицы. Связи между записями задаются внешними ключами, в том числе `ClientId`, `TrainerId`, `HallId` и `SpecializationId`.

Для доступа к данным используются репозитории, реализованные с помощью Entity Framework Core. Изменения сохраняются в базе асинхронно через `SaveChangesAsync`.

Начальная миграция создаёт таблицы и добавляет по 10 записей каждой основной сущности. Начальные данные описаны в классе `SeedData`. При обычном запуске API миграции применяются автоматически. Данные PostgreSQL сохраняются в Docker volume, поэтому они не удаляются при обычном перезапуске контейнера.

Удаление записи, на которую ссылаются другие записи, ограничивается внешними ключами. Конфликт внешнего ключа, уникальности или конкурентного изменения преобразуется в HTTP 409.

Время тренировок передаётся с часовым смещением и хранится в PostgreSQL в UTC (`timestamp with time zone`). Аналитика текущего месяца рассчитывается по UTC. Даты рождения и действия абонементов хранятся как `date`.

## Документация API — Scalar

Для просмотра и тестирования REST API используется Scalar.

Интерактивная документация формируется на основе OpenAPI и предоставляет возможность:

- Просматривать доступные HTTP-методы.
- Изучать маршруты API.
- Просматривать параметры запросов.
- Изучать структуры DTO.
- Отправлять HTTP-запросы непосредственно из браузера.
- Проверять полученные ответы сервера.

После запуска приложения в режиме разработки документация доступна по адресу:

`/scalar/v1`

Спецификация OpenAPI доступна по адресу:

`/openapi/v1.json`

Примеры HTTP-запросов находятся в файле `FitnessClub.Api.http`.

## Обработка ошибок и валидация

Для проверки входных данных используются атрибуты Data Annotations. Проверяются обязательные поля, длины строк, допустимые значения пола, положительные идентификаторы, длительность тренировки, дата рождения и даты действия абонемента.

Основные коды ответов API:

|Код|Описание|
|---|---|
|200|Успешное получение данных|
|201|Запись успешно создана|
|204|Запись успешно обновлена или удалена|
|400|Переданы некорректные данные|
|404|Запись не найдена|
|409|Конфликт ограничений базы данных или конкурентного изменения|
|500|Внутренняя ошибка сервера|

Для обработки конфликтов базы данных используется `DatabaseExceptionHandler`. Неожиданные ошибки обрабатываются стандартным механизмом ASP.NET Core Problem Details. Журналирование HTTP-запросов фиксирует метод, путь и статус ответа.

## Тестирование

Для тестирования используется библиотека xUnit версии 3.

В проекте `FitnessClub.Tests` реализованы проверки аналитических LINQ-запросов и валидации входных данных.

Проверяются следующие операции:

- Получение тренеров со стажем не менее пяти лет.
- Определение доступности зала в заданный момент времени.
- Получение клиентов с истёкшими абонементами.
- Получение тренировок выбранного зала за текущий месяц.
- Получение пяти наиболее востребованных тренеров.
- Отклонение некорректных дат абонемента.
- Отклонение даты рождения из будущего.
- Проверка допустимости значения пола.
- Принятие корректных данных клиента.

Для аналитических тестов используется отдельный набор данных `QueriesTestFixture` с фиксированной датой, что обеспечивает воспроизводимость результатов проверок.

Запуск тестов выполняется командой:

```shell
dotnet test FitnessClub.Tests/FitnessClub.Tests.csproj
```

## Запуск приложения

Для запуска решения используются .NET 10, Docker Desktop с поддержкой Linux-контейнеров и .NET Aspire.

Из каталога `FitnessClub` можно выполнить следующие команды:

```shell
dotnet restore FitnessClub.slnx
dotnet build FitnessClub.slnx
dotnet test FitnessClub.Tests/FitnessClub.Tests.csproj
dotnet run --project FitnessClub.AppHost
```

После запуска Aspire откройте Dashboard по адресу, указанному в терминале. В Dashboard найдите ресурс `fitnessclub-api`, перейдите по его HTTP-адресу и откройте `/scalar/v1`.

Адрес API при запуске через Aspire может отличаться от `localhost:5182`.

Aspire запускает PostgreSQL 17, создаёт базу данных `fitnessclub`, сохраняет её данные в Docker volume, передаёт строку подключения API и ожидает готовности базы перед запуском приложения.

Для отдельного запуска API необходимо самостоятельно запустить PostgreSQL и задать переменную окружения `ConnectionStrings__fitnessclub` со строкой подключения. После этого можно выполнить:

```shell
dotnet run --project FitnessClub.Api --launch-profile http
```

## Миграции

Для создания и проверки миграций используется инструмент `dotnet-ef` версии 10.0.12. Перед выполнением команд необходимо задать переменную окружения `ConnectionStrings__fitnessclub` с корректной строкой подключения к PostgreSQL.

Из каталога `FitnessClub`:

```shell
dotnet tool install --global dotnet-ef --version 10.0.12
dotnet ef migrations add MigrationName --project FitnessClub.Infrastructure.EfCore
dotnet ef migrations has-pending-model-changes --project FitnessClub.Infrastructure.EfCore
```

Для применения миграций вручную используется команда:

```shell
dotnet ef database update --project FitnessClub.Infrastructure.EfCore
```

При обычном запуске API миграции применяются автоматически.
