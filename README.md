# Отчет по лабораторной работе №2: Чистая архитектура и REST API

## Цель работы
Переработка монолитной объектной модели ветеринарной клиники в многослойную Чистую архитектуру (Clean Architecture) с развертыванием асинхронного REST API на платформе .NET 10.

## Архитектура решения (6 проектов)

Приложение разделено на независимые слои согласно принципу инверсии зависимостей (DIP). Зависимости направлены строго внутрь, к ядру системы (Domain).

*   **VetClinic.Domain (Ядро):** Сущности домена (`Pet`, `Vet`, `Owner`), Enums (`Species`, `RepeatVisitIndicator`) и интерфейсы репозиториев (`IRepository<T>`, `IVetRepository`, `IAppointmentRepository`).
*   **VetClinic.Application.Contracts (Контракты):** Плоские структуры обмена данными на базе C# `record` (`PetDto`, `PetCreateUpdateDto`) и интерфейсы прикладных сервисов.
*   **VetClinic.Application (Бизнес-логика):** Реализация прикладных сервисов (маппинг моделей в DTO) и выделенный сервис аналитики `AnalyticService`.
*   **VetClinic.InMemory (Инфраструктура):** InMemory CRUD-репозитории и класс наполнения данных `VetClinicDataSeeder` со свойствами `init` и механизмом деконструкции.
*   **VetClinic.Api.Host (Web-уровень):** REST-контроллеры, сквозное логирование и графический интерфейс Scalar UI.
*   **VetClinic.Tests (Тестирование):** Фикстура `VetClinicFixture` и асинхронные юнит-тесты xUnit v3.

## Ключевые архитектурные решения

### 1. Двухуровневый Dependency Injection (DI)
Сборка зависимостей инкапсулирована внутри конкретных слоев через изолированные методы расширения для `IServiceCollection`:
*   `AddDataLayer()` (слог `InMemory`) — регистрирует `VetClinicDataSeeder` как `Singleton` для сохранения состояния в памяти и репозитории как `Scoped`.
*   `AddApplicationLayer()` (слой `Application`) — регистрирует сервисы маппинга и аналитики.
В `Program.cs` веб-сервера слои подключаются независимо в две строчки.

### 2. Обобщенный `CrudControllerBase`
Для исключения дублирования CRUD-кода (принцип DRY) реализован абстрактный контроллер, автоматизирующий:
*   Маршрутизацию стандартных HTTP-методов (GET, POST, PUT, DELETE).
*   Логирование операций и сквозную обработку исключений (`try-catch`).
*   Формирование статус-кодов REST (`200 OK`, `201 Created`, `204 NoContent`, `404 NotFound`, `500 ServerError`).

### 3. Разделение интерфейсов и моделей (Application.Contracts vs Application)

В решении строго разделены обязанности между описанием логики (проектом контрактов) и её физической реализацией (проектом прикладных сервисов).

*   **Изоляция слоя `VetClinic.Application.Contracts`:**
    Этот проект не содержит исполняемого кода или зависимостей от баз данных. В нем сосредоточены исключительно record-DTO и интерфейсы прикладных сервисов (`IPetAppService`, `IVetAppService`).
*   **Реализация в слое `VetClinic.Application`:**
    Этот проект содержит конкретные классы сервисов, которые реализуют интерфейсы из контрактов. Проект зависит от интерфейсов репозиториев ядра (`Domain`). Сервисы координируют работу приложения: запрашивают доменные сущности из репозиториев, проверяют бизнес-правила.


### 4. InMemory-асинхронность
Для выполнения асинхронного контракта ядра, методы InMemory-репозиториев не используют ключевые слова `async/await`, чтобы избежать построения скрытых стейт-машин компилятора. Результаты из оперативной памяти моментально возвращаются с помощью `Task.FromResult()` и `Task.CompletedTask`.

### 5. Структурированное логирование и веб-интерфейс Scalar
Все сервисы и контроллеры снабжены внедренными логгерами `ILogger<T>` для трассировки шагов бизнес-логики в консоль. Документирование API реализовано через высокопроизводительный движок Scalar UI на базе .NET 10 OpenAPI метаданных.

## Сложные аналитические LINQ-запросы (Реализованы в AnalyticService)

1.  Получение ветеринаров, специализирующихся на выбранном виде животных (`Species`).
2.  Получение питомцев, записанных к указанному врачу, упорядоченных по кличке.
3.  Вычисление количества повторных приемов (`RepeatVisitIndicator.Yes`) для выбранной породы.
4.  Поиск владельцев, имеющих более одного питомца, отсортированных по ФИО.
5.  Выборка приемов за текущий календарный месяц, проходящих в указанном кабинете.

## Запуск приложения

*   **REST API и Scalar UI:** Нажмите **F5** в Visual Studio. Проект автоматически скомпилируется и откроет интерактивную панель управления по адресу `https://localhost:5054/scalar/v1`.
*   **Тесты:** Для выполнения xUnit-тестов в консоли введите `dotnet test`.
