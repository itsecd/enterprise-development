## Реализация

Приложение предоставляет REST API для управления данными фитнес-клуба. API позволяет выполнять CRUD-операции с клиентами, тренерами, специализациями, залами и персональными тренировками, а также получать результаты аналитических запросов.

Данные хранятся в коллекциях в памяти. Для организации приложения используется слоистая архитектура, разделяющая предметную область, контракты, бизнес-логику, инфраструктуру хранения данных и HTTP API.

Для проверки входных данных используются средства валидации Data Annotations. Обработка ошибок и ведение журналов запросов реализованы на уровне API.

Запуск и оркестрация приложения выполняются с помощью .NET Aspire через проект `FitnessClub.AppHost`.

Для просмотра и тестирования HTTP-методов используется интерактивная документация Scalar, основанная на спецификации OpenAPI.

## Архитектура приложения

Решение разделено на отдельные проекты, каждый из которых отвечает за свою часть приложения.

|Проект|Назначение|
|---|---|
|`FitnessClub.Domain`|Сущности предметной области, перечисления и интерфейсы репозиториев|
|`FitnessClub.Contracts`|DTO и интерфейсы прикладных сервисов|
|`FitnessClub.Application`|Бизнес-логика, прикладные сервисы, преобразование сущностей в DTO и аналитические запросы|
|`FitnessClub.Infrastructure.InMemory`|Реализация репозиториев и хранение данных в коллекциях в памяти|
|`FitnessClub.Api`|REST API, контроллеры, обработка HTTP-запросов, валидация и регистрация зависимостей|
|`FitnessClub.AppHost`|Оркестрация и запуск приложения с помощью .NET Aspire|
|`FitnessClub.Tests`|Модульные тесты аналитических LINQ-запросов|

## Хранение данных

Для лабораторной работы используется реализация `FitnessClub.Infrastructure.InMemory`.

В качестве хранилища применяется класс `FitnessClubDataStore`, содержащий коллекции основных сущностей фитнес-клуба:

- Клиенты (`Clients`).
    
- Тренеры (`Trainers`).
    
- Специализации (`Specializations`).
    
- Залы (`Halls`).
    
- Тренировки (`Trainings`).
    

Начальные тестовые данные добавляются с помощью класса `FitnessClubDataSeeder` при инициализации приложения.

Для полноценной проверки аналитических запросов предусмотрено не менее 10 экземпляров каждой основной сущности.

## Документация API — Scalar

Для просмотра и тестирования REST API используется Scalar.

Интерактивная документация формируется на основе OpenAPI и предоставляет возможность:

- Просматривать доступные HTTP-методы.
    
- Изучать маршруты API.
    
- Просматривать параметры запросов.
    
- Изучать структуры DTO.
    
- Отправлять HTTP-запросы непосредственно из браузера.
    
- Проверять полученные ответы сервера.
    

После запуска приложения в режиме разработки документация доступна по адресу:

`/scalar/v1`

Спецификация OpenAPI доступна по адресу:

`/openapi/v1.json`

## Тестирование

Для тестирования используется библиотека xUnit версии 3.

В проекте `FitnessClub.Tests` реализованы тесты аналитических LINQ-запросов.

Проверяются следующие операции:

- Получение тренеров со стажем не менее пяти лет.
    
- Определение доступности зала.
    
- Получение клиентов с истёкшими абонементами.
    
- Получение тренировок выбранного зала за текущий месяц.
    
- Получение пяти наиболее востребованных тренеров.
    

Для тестирования используется отдельный набор данных `QueriesTestFixture` с фиксированной датой, что обеспечивает воспроизводимость результатов проверок.

Запуск тестов выполняется командой:

```
dotnet test
```

## Запуск приложения

Для запуска решения используется проект `FitnessClub.AppHost`.

Из каталога `FitnessClub` можно выполнить следующие команды:

```
dotnet restore
dotnet build
dotnet run --project FitnessClub.AppHost
```

После запуска приложения необходимо открыть предоставленный Aspire адрес API и перейти к интерфейсу Scalar.
