# Ветеринарная клиника (Vet Clinic) — Лабораторная работа №3

Серверное приложение для автоматизации работы ветеринарной клиники, разработанное на платформе **.NET 10 (C#)** с использованием принципов **Clean Architecture**, **REST API** и интеграцией с реляционной СУБД **MySQL** через **Entity Framework Core 9**.

---

## Архитектура проекта (Clean Architecture)

1. **`Vet.Domain`** — ядро системы (доменные сущности, перечисления, интерфейсы репозиториев). Не зависит от внешних библиотек.
2. **`Vet.Contracts`** — контракты данных (раздельные DTO для чтения и создания/обновления с валидацией).
3. **`Vet.Application`** — слой бизнес-логики (CRUD-сервисы, сервис аналитики, маппинг сущностей в DTO).
4. **`Vet.Infrastructure.EfCore`** — слой персистентности: контекст `VetDbContext`, маппинг связей, Code-First миграции и репозитории на базе EF Core (Pomelo MySQL).
5. **`Vet.Infrastructure.InMemory`** — реализация репозиториев в памяти (используется для быстрых модульных тестов).
6. **`Vet.Api`** — презентационный слой (REST-контроллеры, Swagger UI, глобальная обработка ошибок `ProblemDetails`).
7. **`Vet.AppHost` & `Vet.ServiceDefaults`** — оркестрация приложения и инфраструктуры через **.NET Aspire**.
8. **`Vet.Tests`** — модульные тесты сервисов и аналитических запросов.

---

## Реализованный функционал

### 1. CRUD-операции и связи
* Полноценные REST-контроллеры для всех сущностей (`Appointments`, `Breeds`, `Owners`, `Pets`, `Specializations`, `Veterinarians`).
* Вложенные маршруты (Sub-resources) для получения истории приёмов и списков питомцев владельцев.
* Корректная обработка каскадного удаления зависимых данных (делегировано на уровень СУБД `ON DELETE CASCADE`).

### 2. Аналитические запросы (`/api/analytics`)
* Поиск ветеринаров по виду обслуживаемых животных.
* Получение уникальных питомцев конкретного врача (с сортировкой по кличке).
* Подсчет количества повторных приемов для выбранной породы.
* Поиск владельцев с несколькими питомцами.
* Выборка приемов в конкретном кабинете за указанный месяц и год.

## Особенности реализации (Лабораторная работа №3)

* **СУБД MySQL**: Хранение данных переведено с InMemory на полноценную реляционную базу данных.
* **Entity Framework Core**: Использован провайдер `Pomelo.EntityFrameworkCore.MySql` + `MySqlConnector`. Pomelo поддерживает версию EF Core не выше 9, поэтому и была использована ранее упомянутая версия.
* **Code-First & Миграции**: Схема базы данных генерируется миграциями; реализован автоматический накат схемы при старте (`MigrateAsync`).
* **.NET Aspire Orchestration**: Контейнер MySQL поднимается и связывается с API автоматически через `AppHost` с персистентным томом данных (`WithDataVolume`).
* **RFC 7807 (ProblemDetails)**: Централизованная обработка исключений через `IExceptionHandler` (`400`, `404`, `409`, `500`).
