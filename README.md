# Ветеринарная клиника (Vet Clinic) — Лабораторная работа №2

Серверное приложение для автоматизации работы ветеринарной клиники, разработанное на платформе **.NET 10 (C#)** с использованием принципов **Clean Architecture**, **SOLID** и **REST API**.

---

## Архитектура проекта (Clean Architecture)

Решение разбито на изолированные проекты со строго направленными зависимостями:

1. **`Vet.Domain`** — ядро системы (доменные сущности, перечисления, интерфейсы репозиториев и датасидер). Не зависит ни от каких внешних библиотек.
2. **`Vet.Contracts`** — контракты данных (DTO-модели для передачи данных через API, разделенные на GET и POST/PUT).
3. **`Vet.Application`** — слой бизнес-логики (интерфейсы и реализации сервисов CRUD, сервисы аналитики, маппинг).
4. **`Vet.Infrastructure.InMemory`** — слой реализации хранения (In-Memory репозитории).
5. **`Vet.Api`** — презентационный слой (контроллеры REST API, глобальная обработка ошибок через `IExceptionHandler`, Swagger/OpenAPI).
6. **`Vet.Tests`** — юнит тесты, проверяющие аналитические запросы.
7. **`Vet.ServiceDefaults` & `Vet.AppHost`** — инфраструктурные компоненты оркестрации (.NET Aspire).

## Реализованный функционал

### 1. CRUD-операции
Для всех доменных сущностей клиники (`Appointment`, `Breed`, `Owner`, `Pet`, `Specialization`, `Veterinarian`) реализованы полноценные REST-контроллеры, поддерживающие базовые операции:
- `GET /api/{entity}` — получение всех записей.
- `GET /api/{entity}/{id}` — получение записи по идентификатору.
- `POST /api/{entity}` — создание новой записи.
- `PUT /api/{entity}/{id}` — обновление существующей записи.
- `DELETE /api/{entity}/{id}` — удаление записи.

### 2. Связанные маршруты (Sub-resources)
Реализованы эндпоинты для получения коллекций зависимых сущностей:
- `GET /api/owners/{id}/pets` — список всех питомцев конкретного владельца.
- `GET /api/veterinarians/{id}/appointments` — расписание приемов конкретного ветеринара.
- `GET /api/pets/{id}/appointments` — история приемов конкретного питомца.

### 3. Аналитические запросы 
Выделен отдельный контроллер `AnalyticsController` (`/api/analytics`), реализующий выборки с использованием LINQ:
- Получение ветеринаров, специализирующихся на выбранном виде животного.
- Получение уникальных питомцев, записанных к указанному врачу (упорядоченных по кличке).
- Подсчет количества повторных приёмов у выбранной породы.
- Получение владельцев с более чем одним питомцем.
- Получение приёмов в выбранном кабинете за конкретный месяц и год.

### 4. Enterprise-фичи
- **DTO-модели**: Полное разделение на `*Dto` (с вложенными объектами для GET-запросов) и `*CreateUpdateDto` (с плоскими ID для POST/PUT), что полностью исключает циклические ссылки при JSON-сериализации.
- **Глобальная обработка ошибок**: Реализован `GlobalExceptionHandler`, перехватывающий исключения уровня бизнес-логики (`KeyNotFoundException`, `ArgumentException`) и возвращающий клиенту стандартизированный ответ с кодами `404 Not Found` и `400 Bad Request`.
- **Логгирование**: Настроено логгирование в сервисах и контроллерах.
- **Документирование**: Включена генерация XML-документации, интегрированная со Swagger UI.
- **Потокобезопасность**: In-Memory репозитории защищены примитивами синхронизации для корректной работы в многопоточной среде.
