# Лабораторная работа №3 - ORM (Entity Framework Core + PostgreSQL)

## Цель работы

Перевести хранение данных серверного приложения с коллекций в памяти на базу данных PostgreSQL с помощью Entity Framework Core. Создать миграции для таблиц и их первоначального заполнения, а также настроить оркестрацию запуска API и базы данных через .NET Aspire.

## Архитектура проекта

Для соблюдения принципов чистой архитектуры (Clean Architecture) проект разделен на слои:

- `AutoService.Domain` — доменные модели и интерфейсы репозиториев.
- `AutoService.Contracts` — DTO (Data Transfer Objects) и интерфейсы сервисов.
- `AutoService.Application` — бизнес-логика (сервисы, маппинг, аналитика).
- `AutoService.Infrastructure` — реализация репозиториев на Entity Framework Core, `AutoServiceDbContext`, конфигурации сущностей и миграции.
- `AutoService.Api` — контроллеры, настройка DI и JWT-авторизации.
- `AutoService.AppHost` — проект оркестратора .NET Aspire для запуска API и базы данных.

## База данных и миграции

В качестве СУБД используется PostgreSQL. Работа с ней настроена через Fluent API (`IEntityTypeConfiguration`):
- Настроены связи: один-ко-многим (Клиент — Автомобили), многие-ко-многим (Заказы — Виды работ).
- Удаление связанных сущностей ограничено (`DeleteBehavior.Restrict`).
- Специализация механика сохраняется строкой.
- Вычисляемое свойство `TotalCost` в базе не сохраняется (настроено через `Ignore`).

Созданы миграции:
1. `InitialCreate` — создает таблицы и заполняет их начальными данными из `DataSeed`.
2. `AddUserAuthentication` — добавляет таблицу `users` для администратора.

Для детерминированного заполнения (чтобы ID записей не менялись при пересоздании БД) в `DataSeed` заданы фиксированные `Guid`.

Команды для работы с миграциями, как пример:
```commandline
dotnet ef migrations add InitialCreate --project AutoService.Infrastructure --startup-project AutoService.Api
dotnet ef database update --project AutoService.Infrastructure --startup-project AutoService.Api
```

## Аутентификация (JWT)

Все рабочие эндпоинты (кроме логина) требуют авторизации. Добавлен `AuthController` и `AuthService`.
- Логин: `admin`
- Пароль: `Admin123!`

Пароль хранится в БД в виде хеша. Для получения токена нужно отправить `POST /api/auth/login`. Токен выдается на 1 час и передается в заголовке `Authorization: Bearer <токен>`.

## Реализованный функционал

**1. CRUD-операции:**
Реализованы контроллеры для управления всеми основными сущностями (Cars, Clients, Mechanics, Orders, Works). Для каждой сущности доступны методы `GET`, `POST`, `PUT` и `DELETE`. Взаимодействие происходит через DTO. Для методов обновления используются отдельные DTO без поля `Id`.

**2. Аналитические запросы:**
Логика 5 запросов из первой лабораторной вынесена в `ReportsController` и доступна по HTTP:
1. Получение механиков, специализирующихся на выбранном виде работ.
2. Получение клиентов, чьи автомобили обслуживались у указанного механика, с сортировкой по ФИО.
3. Получение клиентов с повторными обращениями за последний месяц.
4. Подсчёт суммарной стоимости работ для выбранного заказа.
5. Получение пяти наиболее частых видов работ.

**3. Обработка исключений:**
Для аккуратной обработки ошибок добавлен глобальный `ExceptionHandlingMiddleware`. Он перехватывает непредвиденные исключения (включая ошибки БД), логирует их и возвращает клиенту корректный статус (500 или 409 Conflict). Ожидаемые ситуации (например, 404 Not Found) обрабатываются в контроллерах.

## Интерфейс приложения (Swagger)

Для удобства тестирования и документирования эндпоинтов подключен Swagger UI. Настроено отображение XML-комментариев (`summary`) из кода. При запуске проекта браузер автоматически открывается на странице Swagger. Для проверки защищенных методов необходимо авторизоваться, нажав кнопку **Authorize**, и вставить полученный JWT-токен.

## Тестирование

Для тестирования используется **xUnit v3**. Тесты разделены на два проекта:
- `AutoService.Tests` — 5 юнит-тестов на LINQ (из ЛР1, работают по `DataSeed`).
- `AutoService.IntegrationTests` — 2 интеграционных теста (`ApiIntegrationTests`), которые запускают оркестратор **.NET Aspire** с контейнером PostgreSQL, получают JWT-токен и проверяют ответы HTTP-эндпоинтов (включая проверку ответа 401 Unauthorized без токена). Оркестратор поднимается один раз для всех тестов с помощью общей фикстуры `AspireAppFixture` (xUnit collection fixture).

С помощью команды
```commandline
dotnet test
```
получим результат выполнения:
```commandline
Сводка тестового запуска: Пройден!
  итог: 7
  сбой: 0
  успешно: 7
  пропущено: 0
  длительность: 32s 987ms
```
Длительность тестового запуска объясняется запуском Aspire: перед интеграционными тестами поднимаются контейнер с PostgreSQL и само приложение.

## Запуск
1. Восстановить зависимости: `dotnet restore`
2. Запустить оркестратор Aspire (требуется установленный Docker): `dotnet run --project AutoService.AppHost`
3. Открыть в браузере документацию Swagger по адресу: `http://localhost:5199/swagger`.

Запуск также осуществляется через IDE: необходимо запустить проект AutoService.AppHost, и браузер со страницей Swagger UI откроется автоматически.
