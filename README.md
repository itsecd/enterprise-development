# VeterinaryClinic

## Архитектура и проверки

- `Domain.Models` содержит сущности, `Domain.Repositories.IRepository<T>` — единственный контракт хранилища.
- Application.Contracts организован по ресурсам; Application.Services содержит операции и бизнес-проверки.
- Для нового или изменяемого приёма проверяется дата и отсутствие другого приёма в том же кабинете в тот же момент времени.
- Для ветеринара проверяются возраст и непротиворечивость указанного стажа.
- Существующие исторические приёмы остаются в начальных данных; ограничение по дате применяется к новым и изменяемым записям.

Для проверки: `dotnet build VeterinaryClinic.slnx` и `dotnet test VeterinaryClinic.slnx`.

## Лабораторная работа 3: PostgreSQL

API использует PostgreSQL через EF Core и .NET Aspire. При запуске API без Aspire необходимо задать строку подключения `ConnectionStrings__clinicdb`. Переключения на хранилище в памяти в API нет.

Идентификаторы генерирует PostgreSQL. Связи сущностей настроены в `ClinicDbContext`. Аналитический запрос владельцев нескольких питомцев выполняется на стороне базы данных.

Миграция `InitialSchema` находится в `VeterinaryClinic.Infrastructure.PostgreSQL/Migrations`. При запуске API автоматически применяются ожидающие миграции.

Для первоначального применения миграции используйте новую пустую базу данных. Не применяйте её поверх старой схемы, созданной вручную, без предварительной проверки и резервного копирования. Начальные данные содержат фиксированные даты приёмов в ноябре 2026 года, поэтому в другие месяцы запрос приёмов текущего месяца может вернуть пустой список.

Репозитории в памяти используются только в модульных тестах сервисов; рабочий API подключается исключительно к PostgreSQL.
