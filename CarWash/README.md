## Реализация

В работе описаны автомобили, клиенты, услуги и заказы автомойки. Данные хранятся в памяти. Пять аналитических запросов реализованы средствами LINQ в модульных тестах xUnit v3.

| Тип | Назначение |
|---|---|
| `Vehicle` | Автомобиль: государственный номер, марка и категория |
| `VehicleCategory` | Категории транспорта: легковой автомобиль, грузовой автомобиль, мотоцикл |
| `Client` | Клиент: ФИО, телефон и коллекция принадлежащих ему автомобилей |
| `Service` | Услуга: название, цена, длительность в минутах и категория транспорта |
| `Order` | Заказ: клиент, автомобиль, услуга, дата и время начала обслуживания, номер бокса |

Категория дополнительно хранится в автомобиле. В тестовых данных категория каждой заказанной услуги соответствует категории автомобиля, а автомобиль принадлежит клиенту заказа.

## Тестовые данные

`CarWashFixture` создаёт ровно по 10 экземпляров `Vehicle`, `Client`, `Service` и `Order`. Заказы и списки автомобилей клиентов используют ссылки на уже созданные объекты из коллекций фикстуры.

Данные вымышленные и фиксированные. В них предусмотрены повторные посещения, клиенты с несколькими автомобилями, клиенты без заказов, услуги без продаж и равные значения популярности. Заказы расположены не в хронологическом порядке. Обслуживание в одном боксе и обслуживание одного автомобиля не пересекаются по времени.

Для проверки текущей загрузки используется `ReferenceTime`: **14 сентября 2026 года, 10:00:00**. Времена трактуются как местное время одного условного расписания без преобразования часовых поясов. Датасид содержит завершённые, текущие и будущие заказы, а также случаи точного совпадения начала или окончания обслуживания с моментом проверки.

Тестовый класс получает общую фикстуру через `IClassFixture<CarWashFixture>`. Все пять тестов только читают её данные.

## Аналитические тесты и принятые правила

Каждый тест построен по схеме Arrange — Act — Assert: задаётся ожидаемый результат, выполняется LINQ-запрос, затем проверяется соответствие результата ожиданиям.

| Запрос | Что проверяется |
|---|---|
| Топ-5 клиентов по числу посещений | Конкретные клиенты, их порядок и число посещений |
| Автомобили на мойке в заданный момент | Точный состав автомобилей и порядок соответствующих заказов |
| Топ-5 услуг по числу заказов | Конкретные услуги, их порядок и число заказов |
| Время освобождения выбранного бокса | Окончание всех запланированных работ в боксе с существующими заказами |
| Выручка по каждой услуге | Сумма для каждой услуги, включая нулевую сумму для услуг без заказов |

Правила интерпретации данных:

- В рейтингах каждый заказ считается одним посещением клиента и одним использованием услуги. Учитываются все заказы датасида без фильтра по времени.
- Рейтинги сортируются по убыванию количества заказов. При равенстве используется полное имя клиента или название услуги с `StringComparer.Ordinal`. Клиенты и услуги без заказов в рейтинги не входят.
- Автомобиль находится на мойке в интервале `начало <= момент проверки < окончание`. Окончание определяется прибавлением длительности услуги в минутах к времени начала.
- Освобождение бокса трактуется как окончание всех записанных в расписание работ, включая будущие. Тест проверяет расписание без пересечений; при нём заказ с самым поздним началом заканчивается последним. Для бокса № 1 ожидается **14 сентября 2026 года, 11:30:00**.
- Выручка рассчитывается по всем заказам с использованием цены соответствующей услуги в датасиде. Суммы возвращаются в порядке коллекции `Services`. Общая сумма по датасиду — **8000**.

## Требования к среде

- .NET SDK 10.0.
- Для работы через IDE — Visual Studio Community 2026 с поддержкой разработки на .NET.
- Доступ к NuGet для первоначального восстановления зависимостей.

Используются `net10.0`, xUnit v3 и Microsoft Testing Platform v2. Тесты выполняются над коллекциями в памяти.

В `global.json` выбран последний установленный стабильный SDK ветки .NET 10.0, начиная с версии 10.0.100. Предварительные версии и переход на .NET 11 не используются.

## Запуск в Visual Studio

1. Открыть `CarWash.slnx` из этой папки.
2. Сохранить файлы и собрать решение.
3. Открыть **Тест → Обозреватель тестов**.
4. Запустить все тесты проекта `CarWash.Tests`.

Ожидаемый результат: **5 успешно выполненных тестов**.

## Запуск из терминала

Выполнить из корневой папки репозитория `enterprise-development`, где находится `global.json`:

```sh
dotnet test --solution CarWash/CarWash.slnx
```

Команда восстанавливает зависимости, собирает проекты и запускает тесты. Для выбранного в `global.json` Microsoft Testing Platform путь к решению передаётся через параметр `--solution`.

Успешный запуск завершается с кодом `0` и сообщает о пяти пройденных тестах. При ошибке в выводе указаны тест, причина и, при несовпадении результатов, ожидаемое и фактическое значения.

## GitHub Actions

Workflow [CarWash CI](../.github/workflows/carwash-ci.yml) запускается при отправке изменений в ветки `lab1` и `main`, а также при создании и обновлении pull request в `main`.

На машине GitHub с Ubuntu последовательно выполняются:

1. Получение кода репозитория.
2. Установка стабильного .NET SDK 10.0.
3. Восстановление зависимостей решения.
4. Сборка в конфигурации `Release`.
5. Запуск тестов без повторной сборки. Проверка требует выполнения как минимум пяти тестов.

Результат доступен во вкладке **Actions → CarWash CI → Build and test**. Для этого workflow не требуется добавлять секреты или API-ключи.
