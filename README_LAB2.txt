DryCleaning — лабораторная работа № 2 «Сервер»

Курс «Разработка корпоративных приложений». REST API для химчистки на ASP.NET Core и .NET 10. Приложение использует модель данных из первой лабораторной работы. Данные хранятся в памяти.

Параметры проекта:
Автор: Мельник Александр
Группа: 6412
Вариант: 50
Предметная область: Химчистка
Технологии: .NET 10, ASP.NET Core, xUnit v3, Swagger

Состав решения:
DryCleaning.slnx
DryCleaning.Domain — сущности, перечисления, интерфейсы репозиториев, сиды TestData.
DryCleaning.Contracts — DTO, интерфейсы сервисов, исключения.
DryCleaning.Application — бизнес-правила, аналитика, преобразование в DTO.
DryCleaning.Infrastructure.InMemory — репозитории для работы с коллекциями в памяти.
DryCleaning.Api — HTTP-контроллеры, глобальный middleware, Program.cs.
DryCleaning.Tests — тесты аналитических LINQ-запросов из первой лабораторной.

Архитектура:
Контроллеры получают интерфейсы сервисов через конструктор и работают с DTO. Сервисы проверяют данные, выполняют бизнес-правила и аналитические запросы, обращаются к репозиториям и преобразуют доменные объекты в DTO. Репозитории читают и изменяют коллекции TestData.
Интерфейсы репозиториев находятся в Domain, а их реализации — в Infrastructure.InMemory. Интерфейсы сервисов находятся в Contracts, реализации — в Application. Все операции сервисов и репозиториев возвращают Task. В Program.cs зарегистрированы все сервисы и репозитории.
При запуске TestData создаёт 10 клиентов, 10 категорий, 10 изделий и 12 заказов. API использует один экземпляр этих данных (через Singleton). Созданные и изменённые записи не сохраняются на диск и возвращаются к исходному состоянию после перезапуска приложения.

DTO и проверки данных:
Клиент: ClientDto (ответ), ClientEditDto (создание, изменение).
Категория: ItemCategoryDto (ответ), ItemCategoryEditDto (создание, изменение).
Изделие: ItemDto (ответ), ItemEditDto (создание, изменение).
Заказ: OrderDto (ответ), OrderCreateDto (создание), OrderEditDto (изменение).
Входные DTO используют атрибуты валидации. Имя клиента ограничено 100 символами, телефон — 20 символами и проверяется атрибутом Phone. Название категории ограничено 50 символами, цена должна быть больше нуля и не превышать 10 000 000. Название и материал изделия ограничены 100 символами. Идентификаторы связанных записей и плановый срок обработки должны быть положительными, виды обработки и статусы — допустимыми значениями enum.

REST API:
Для каждой сущности доступны GET списка, GET по ID, POST, PUT по ID и DELETE по ID.
Клиенты: /api/clients и /api/clients/{id}
Категории: /api/categories и /api/categories/{id}
Изделия: /api/items и /api/items/{id}
Заказы: /api/orders и /api/orders/{id}
Заказы ссылаются на существующих клиентов и изделия, а изделия — на существующие категории. Нельзя удалить клиента или изделие с заказами либо категорию с изделиями: сервер возвращает 409 Conflict. Для некорректных данных используется 400 Bad Request, для отсутствующей записи — 404 Not Found. Успешное создание возвращает 201 Created, а изменение и удаление — 204 No Content.
Новый заказ получает статус Accepted и время приёма в UTC. При изменении заказа дата завершения обязательна для статусов Completed и Issued, а для остальных статусов должна быть пустой.
Для получения связанных записей доступны:
GET /api/clients/{clientId}/orders — заказы клиента.
GET /api/categories/{categoryId}/items — изделия категории.
Если клиент или категория существуют, но связанных записей нет, возвращается 200 OK с пустым массивом. Если не найдены — 404 Not Found.

Аналитические запросы:
GET /api/orders/in-progress — заказы в обработке, отсортированные по дате приёма (ID 9, 7, 1).
GET /api/clients/top?start=2026-01-01&end=2027-01-01 — пять клиентов по числу принятых изделий.
GET /api/clients/top-spender — клиент с наибольшей суммой выданных заказов.
GET /api/clients/longest-processing — клиенты с максимальной фактической длительностью обработки.
GET /api/categories/popularity?end=2026-12-31 — наиболее и наименее популярные категории за год.
В запросах за период начальная дата включается, конечная — нет. Для рейтинга клиентов параметры start и end обязательны; отсутствие любого из них возвращает 400 Bad Request. Отменённые заказы не участвуют в рейтингах клиентов и категорий. Расходы клиента считаются по текущей цене категории изделия.

Запуск и проверка:
Требуется .NET SDK 10. Из папки DryCleaning запустить API:
dotnet run --project DryCleaning.Api
В режиме Development Swagger UI доступен по адресу http://localhost:5100/swagger (порт может отличаться, смотрите вывод в консоли).
Для ручной проверки можно использовать Swagger UI (кнопка Try it out) или выполнять HTTP-запросы через файл .http.
Для запуска тестов xUnit v3 из той же папки:
dotnet test DryCleaning.slnx
Тесты проверяют аналитические LINQ-запросы из первой лабораторной работы на фиксированном наборе данных. Они не отправляют HTTP-запросы к API.
